# 并发寻优协议

对每一个（布局 × 序列 × 特性组合），要找的是：**满足全部门限的最大并发，以及该并发下的单卡输出吞吐**。

基本关系：并发上升 → 输出吞吐上升、TPOT 上升。所以门限内的最优点就在 TPOT 刚好不超限的那一侧。这是经验规律而非定理，遇到反例按本文第 5 节处理。

## 1. 选起点

| 卡数 | 粗扫序列 |
|---|---|
| 1 卡 | 2, 4, 8, 12, 16, 24, 32 |
| 2 卡 | 4, 8, 16, 24, 32, 48 |
| 4 / 8 卡 | 24, 32, 48, 64, 80, 96, 128 |

长序列（64k/1k、128k/1k）受显存限制，起点要先按 [服务化基线](serving-baseline.md#5-显存与块数) 的块数估算压一压，1 卡 128k 往往只能跑个位数并发。

起点还要和图捕获上限对照：如果粗扫序列会直接跨过 `max(capture_sizes) / (k+1)`，先标注这个位置，后面解释拐点时用得上。

## 2. 粗扫

从起点逐级上调，直到 TPOT 平均首次越过上限。记录首个超限并发 `C_bad` 和它前一个达标并发 `C_good`。

每个点都是：重启服务（或确认服务状态干净）→ 跑 AISBench → 做请求级校验 → 落盘。不要为了省时间在同一服务上连着跑多个并发而不清 prefix cache；普通用例尤其会被上一轮的缓存污染。

## 3. 细扫

在 `(C_good, C_bad)` 区间内二分，直到相邻整数。门限点可能很窄：本项目 DP1-TP1 的典型形态是并发 16 时 TPOT 约 25ms 超限、12 时约 15ms，真正的最优落在 13–14。

细扫到相邻整数后，报告里必须同时给出最优点和它右边第一个超限点。只给一个达标点无法证明它是最大值。

TPOT 落在门限 ±1ms 以内的点，重复测一次确认不是噪声；两次都达标才算达标。

## 4. 收敛与上界

以下任一条件满足就停止上调并发：

- TPOT 已超限且再上调没有意义；
- 并发超过显存可容纳请求数（出现抢占、重算、请求排队）；
- 出现 OOM、EngineDead、KV 传输错误等致命模式——该候选判无效，不是"性能差"；
- 吞吐随并发上升已经饱和甚至下降，且 TPOT 仍在上升。

## 5. 非单调与断崖

TPOT 出现数倍突变时，按这个顺序查，不要直接重测或归为噪声：

1. **图捕获边界**：并发 ×（投机 token 数 + 1）是否越过 `max(cudagraph_capture_sizes)`。越过即回退 eager，这是最常见的原因，断崖幅度通常 3–6 倍。
2. **显存块数耗尽**：请求被抢占重算，日志里有 preemption 计数。
3. **调度回退**：`--max-num-batched-tokens`、`--max-num-seqs` 限制住了组批。
4. **命中率塌陷**：长序列预热失效，TTFT 和 TPOT 一起恶化。

确认是配置边界后，另起一个只改该项的变体做对照（例如捕获范围 192 → 512 token），base 变体保持不动。对照结论要用实测说话，源码推断只能写成"有源码支持的原因推断，待对照数据证实"。

## 6. 单卡输出吞吐

```text
单卡输出吞吐 = 输出吞吐(tps) / 归一卡数
```

归一卡数：混部取该实例占用的 NPU 数；PD 分离取 P 与 D 的全部 NPU 数之和。proxy 不计卡。

比较不同布局时只比这一个数，不要用总吞吐，也不要用请求吞吐替代。

## 7. 特性对照

base 的最优点拿到后才叠加特性，一次一个变量：

1. 复制 base 的服务脚本，只改这一个开关；
2. 重新走完整的粗扫 + 细扫（特性会改变拐点位置，不能复用 base 的最优并发）；
3. 对照表里记两侧各自的最优并发与单卡输出。

不同配置的最优并发不同，所以这个差值是"各自最优点之间的差"，不能表述为固定负载下某算子的加速比。

特性不可用时（版本不支持、启动被显式拒绝），保留真实的启动错误，记 blocked，不要写成吞吐 0。

## 8. 搜索记录

每条序列保存一个 `search.json`，内容至少包括：

```json
{
  "layout": "c8-n4-dp1-tp4-base",
  "case": [4096, 2048],
  "tpot_limit_ms": 20,
  "points": [
    {"concurrency": 24, "tpot_avg_ms": 12.7, "per_card_output_tps": 430.99, "valid": true, "pass": true},
    {"concurrency": 48, "tpot_avg_ms": 18.3, "per_card_output_tps": 605.11, "valid": true, "pass": true},
    {"concurrency": 52, "tpot_avg_ms": 72.0, "per_card_output_tps": 175.99, "valid": true, "pass": false}
  ],
  "first_exceeding_concurrency": 52,
  "best": {"concurrency": 48, "per_card_output_tps": 605.11},
  "notes": "52 并发处的突变与 MTP3 下 192-token 捕获上限（48 请求）吻合"
}
```

所有点都进 `points`，包括超限和无效的。`best` 只能从 `valid && pass` 的点里取。
